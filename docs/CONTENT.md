# Content: generators and content packs

All built-in builds are **original** and generated by code in `packages/content` (CC0 1.0). No external schematics
are used.

## Writing a generator

```ts
import { Builder, woodSet, roofSet } from "../lib/builder";
import { door, gableRoof, windowRow, lantern } from "../lib/parts";

export function shed(p: { wood: "oak" | "spruce" }): Builder {
  const w = woodSet(p.wood);
  const b = new Builder(12, 10, 10); // generous bounds; finish() trims them
  b.floor(2, 2, 8, 6, 0, "cobblestone"); // role: foundation
  b.walls(2, 2, 8, 6, 1, 3, w.planks, "walls", w.log); // corner logs get role "frame"
  door(b, 5, 1, 6, "south", w.door); // both halves, role "openings"
  windowRow(b, "x", 2, 4, 6, 2, 2); // glass panes
  b.fill(2, 4, 2, 8, 4, 6, w.planks, "walls"); // ceiling — roofs start on the same layer
  gableRoof(b, 2, 2, 8, 6, 4, roofSet("spruce"), { axis: "x", gable: w.planks });
  lantern(b, 5, 3, 4, true); // hanging, deferred until the ceiling exists
  return b;
}
```

Rules that keep builds **buildable by hand** (checked by `packages/content/test/catalog.test.ts`):

- every block needs a face neighbour placed earlier, or the ground (y = 0);
- start a roof on the **same layer as the ceiling** so the first stair row touches it;
- hip and cone roofs put a ring of full blocks under each next ring (`hipRoof`/`coneRoof` do this);
- open gables or overhangs > 1 use `underFill` (default in `gableRoof`) or a `deck`;
- decorations standing on terrain should get a block underneath (e.g. a stone footing).

Add the generator to `src/catalog.ts` with bilingual title/description, style, tags and parameters, then run:

```bash
pnpm content:build
```

```bash
pnpm render:previews
```

Useful helpers: `ring`, `walls`, `fill`, `circle`, `gableRoof`, `hipRoof`, `coneRoof`, `flatRoof`, `door`,
`windowRow`, `shutters`, `flowerBox`, `wallTorch`, `lantern`, `bed`, `table`, `chair`, `furniture`, `carpet`,
`bush`, `tree`, `chimney`. `pnpm --filter @kladka/content exec tsx src/dev/scaffold-report.ts <id>` lists blocks that
would need scaffolding.

## Content pack format

```
my-pack.zip
├── pack.json
├── builds/
│   ├── cottage.kbuild        # or .schem / .litematic / .nbt
│   └── tower.litematic
└── previews/…                # optional
```

`pack.json`:

```json
{
  "format": "kladka-pack",
  "version": 1,
  "id": "my-pack",
  "name": { "ru": "Мой пак", "en": "My pack" },
  "author": "Your name",
  "license": "CC-BY-4.0",
  "createdAt": "2026-11-07",
  "game": "minecraft-java",
  "builds": [
    {
      "id": "cottage",
      "file": "builds/cottage.kbuild",
      "meta": {
        "id": "cottage",
        "title": { "ru": "Коттедж", "en": "Cottage" },
        "description": { "ru": "…", "en": "…" },
        "author": "Your name",
        "license": "CC-BY-4.0",
        "createdAt": "2026-11-07",
        "style": "rustic",
        "tags": ["small"]
      }
    }
  ]
}
```

Users add packs via **Import** (the `.zip` is processed locally). Only distribute builds you created or have
permission to share; record the author and license in `meta`.

## `.kbuild`

Gzip-compressed JSON (`format: "kladka-build", version: 1`): `size`, `palette` (block-state strings), `blocks`
(base64 of varint run-length pairs), optional `roles` (same encoding, role codes 1..8), `meta` (BuildMeta).
