## Шаг 3. Репозиторий на GitHub и первая сборка

Сборки для Android и компьютера делает GitHub: на этом компьютере нет ни Android SDK, ни Rust. Пока код не
отправлен, ни одна из этих сборок ни разу не запускалась, поэтому при первом запуске что-то может упасть — это
ожидаемо и чинится по тексту ошибки.

### 3.1. Решите, каким адресом подписаны коммиты

В истории проекта каждый коммит подписан вашим адресом почты из настроек git. В публичном репозитории его увидит
любой. Варианты:

- оставить как есть;
- попросить помощника до отправки заменить адрес во всех коммитах на служебный адрес GitHub вида
  `ЧИСЛО+ЛОГИН@users.noreply.github.com` (он показан на странице github.com → Settings → Emails). Пока код никуда
  не отправлен, это безопасно.

### 3.2. Создайте репозиторий

1. Войдите на github.com (или зарегистрируйтесь).
2. Нажмите «+» справа вверху → **New repository**.
3. **Repository name:** `kladka`.
4. **Public.** Для публичного репозитория сборки и страница веб-версии бесплатны; для закрытого страница
   веб-версии на бесплатном тарифе не работает, а минуты сборки ограничены.
5. Галочки «Add a README», «Add .gitignore», «Choose a license» **не ставьте** — репозиторий должен быть пустым.
6. Нажмите **Create repository**.

### 3.3. Включите страницу веб-версии

В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**. Больше ничего на этой
странице менять не нужно.

### 3.4. Отправьте код

Проще всего написать помощнику: «отправь код в https://github.com/cacheshellpassage/kladka». При первой отправке Windows
откроет окно входа в GitHub — войдите в нём сами.

То же вручную, в папке проекта (подставьте свой логин):

```bash
git remote add origin https://github.com/cacheshellpassage/kladka.git
```

```bash
git push -u origin main
```

### 3.5. Дождитесь сборок

Откройте вкладку **Actions** репозитория. Запустятся четыре сборки:

| Сборка              | Что делает                                      | Что получится                                      |
| ------------------- | ----------------------------------------------- | -------------------------------------------------- |
| CI                  | проверки кода, тесты, сборка веб-версии         | зелёная галочка                                    |
| Android (Capacitor) | собирает APK и AAB                              | архив `android-apk` в разделе Artifacts            |
| Desktop (Tauri)     | собирает установщики для Windows, Linux и macOS | архивы `desktop-…` в разделе Artifacts             |
| PWA on GitHub Pages | выкладывает веб-версию                          | сайт `https://cacheshellpassage.github.io/kladka/` |

Сборки идут от нескольких минут до получаса (дольше всего — Desktop).

### 3.6. Если сборка красная

1. Нажмите на красную сборку, затем на задание с красным крестиком.
2. Раскройте шаг с крестиком и скопируйте последние 30–50 строк.
3. Пришлите их помощнику — он исправит и отправит снова.

**Готово, когда:** все четыре сборки зелёные и сайт `https://cacheshellpassage.github.io/kladka/` открывается.

## Шаг 4. Ключ подписи и подписанный APK

Ключ подписи доказывает, что обновление выпустили именно вы. **Без ключа и паролей выпустить обновление нельзя**,
восстановить их невозможно. Создаёте и храните ключ только вы: помощник пароли не видит и не вводит.

### 4.1. Создайте ключ

В PowerShell создайте папку:

```powershell
mkdir C:\keys
```

Создайте ключ (на этом компьютере `keytool` уже есть в составе Java):

```powershell
& "C:\Program Files\Java\jre1.8.0_501\bin\keytool.exe" "-J-Duser.language=en" -genkeypair -v -keystore C:\keys\kladka-release.jks -alias kladka -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=Kladka"
```

Программа спросит:

1. `Enter keystore password` — придумайте пароль (не короче 6 знаков, латиница и цифры) и введите его дважды.
   Символы при вводе не отображаются — это нормально.
2. `Enter key password for <kladka>` — нажмите Enter: пароль ключа будет тем же.

Предупреждение про «proprietary format» можно не читать — файл подходит.

Если после обновления Java путь изменился, найдите `keytool.exe` в `C:\Program Files\Java\…\bin`.

### 4.2. Сохраните ключ и пароль

- Файл `C:\keys\kladka-release.jks` скопируйте в два места вне этого компьютера (флешка, облачный диск).
- Пароль запишите в менеджер паролей или на бумагу.
- В папку проекта файл не кладите. На случай ошибки `.gitignore` не пропускает `*.jks`, но лучше не проверять.

### 4.3. Добавьте секреты в репозиторий

Скопируйте содержимое ключа в буфер обмена в виде текста:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("C:\keys\kladka-release.jks")) | Set-Clipboard
```

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**. Создайте четыре секрета:

| Name                       | Secret                             |
| -------------------------- | ---------------------------------- |
| `KLADKA_KEYSTORE_BASE64`   | вставьте из буфера обмена (Ctrl+V) |
| `KLADKA_KEYSTORE_PASSWORD` | пароль из пункта 4.1               |
| `KLADKA_KEY_ALIAS`         | `kladka`                           |
| `KLADKA_KEY_PASSWORD`      | тот же пароль                      |

### 4.4. Пересоберите APK

**Actions → Android (Capacitor) → Run workflow → Run workflow** (ветка `main`).

**Готово, когда:** в архиве `android-apk` этой сборки лежит `apk/release/app-release.apk`. Если файл называется
`app-release-unsigned.apk`, секреты не подхватились — проверьте их названия.

## Шаг 5. Проверка APK на телефоне

### 5.1. Установка

1. На странице зелёной сборки Android внизу, в разделе **Artifacts**, скачайте `android-apk` (это zip).
2. Достаньте `apk/release/app-release.apk` и передайте на телефон (кабель, облачный диск, сообщение самому себе).
3. Откройте файл на телефоне и разрешите установку из этого источника, когда Android спросит.

Нужен Android 7.0 или новее. Если раньше ставили отладочную версию (`app-debug.apk`), сначала удалите её: у неё
другая подпись.

### 5.2. Что пройти

Включите авиарежим — приложение обязано работать без сети.

| №   | Действие                                                           | Должно быть                                               |
| --- | ------------------------------------------------------------------ | --------------------------------------------------------- |
| 1   | Запустить приложение                                               | открывается каталог с обложками, название «Кладка»        |
| 2   | Открыть «Мини-замок» → «Начать строить»                            | 3D-вид и карточка шага, шаг 1 из 80                       |
| 3   | Пролистать 10–15 шагов свайпом и кнопками                          | шаги меняются, блоки шага подсвечены                      |
| 4   | Вкладка «Схема»: щипок, сдвиг пальцем, двойное касание             | схема увеличивается и двигается, появляется кнопка сброса |
| 5   | Повернуть 3D-вид пальцем, приблизить щипком                        | вращается плавно, без рывков                              |
| 6   | Режим «Я в игре»: листать свайпом, подождать минуту                | крупный номер шага, экран не гаснет                       |
| 7   | Дойти до шага 45                                                   | надпись «Одинаковых частей: 4…»                           |
| 8   | Повернуть телефон горизонтально и обратно                          | раскладка перестраивается, шаг не сбрасывается            |

### 5.3. Что прислать, если что-то не так

Модель телефона, версию Android, номер строки из таблицы, что произошло и снимок экрана. Помощник исправит,
после чего сборка и проверка повторяются.

**Готово, когда:** все строки пройдены хотя бы на одном телефоне; лучше — ещё и на одном слабом.

## Шаг 6. Проверка экспорта в игре

Экспорт проверен тестами по описаниям форматов, но ни разу не открывался в самой игре.

1. В веб-версии или на телефоне откройте «Мини-замок» и экспортируйте его в трёх форматах.
2. Проверьте каждый файл:

| Формат       | Чем открыть                  | Куда положить файл                                          | Как загрузить                                              |
| ------------ | ---------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| `.nbt`       | структурный блок (без модов) | `.minecraft/saves/ИМЯ_МИРА/generated/minecraft/structures/` | структурный блок в режиме «Загрузка», имя файла без `.nbt` |
| `.litematic` | мод Litematica               | `.minecraft/schematics/`                                    | меню Litematica → Load Schematics                          |
| `.schem`     | мод или плагин WorldEdit     | `.minecraft/config/worldedit/schematics/`                   | `//schem load имя`, затем `//paste`                        |

3. Сравните с 3D-видом в приложении: постройка целая, ступени, двери и люки повёрнуты правильно, нет лишних и
   пропавших блоков.

Структурный блок загружает не больше 48×48×48 блоков за раз — мини-замок помещается. Если модов для вашей версии
игры ещё нет, достаточно проверки `.nbt`.

**Готово, когда:** хотя бы `.nbt` загрузился и постройка выглядит как в приложении. О расхождениях сообщите
помощнику со снимком экрана.

## Шаг 8. Публикация в RuStore

Названия кнопок в консоли могут немного отличаться — RuStore их меняет.

### 8.1. Аккаунт разработчика

1. Откройте https://www.rustore.ru/developer и нажмите **В консоль**.
2. **Войти через VK ID** — по номеру телефона; если аккаунта VK ID нет, создайте его.
3. Тип аккаунта — **Физическое лицо** → **Продолжить**.
4. Проверьте данные → **Подтвердить**.

Публикация бесплатная.

### 8.2. Приложение и файл

1. Вкладка **Приложения** → **Добавить приложение** → название «Кладка» → **Добавить**.
2. Откройте приложение → **Загрузить версию**. Тип — универсальный (телефон и планшет), не ТВ.
3. Загрузите `app-release.apk` из шага 4. Не закрывайте страницу, пока идёт загрузка.

Загружайте именно APK, а не AAB: для AAB ключ подписи пришлось бы отдельно передавать в RuStore. Обработанный
файл хранится 14 дней — за это время версию нужно отправить на модерацию.

Отправьте версию на модерацию и ждите письма. Если версию отклонят, в комментарии будет указана причина —
перешлите её помощнику. Самые вероятные замечания для этого приложения:

- **чужой товарный знак** — из-за упоминания игры в описании; отвечайте текстом комментария выше, при
  необходимости упоминание можно сократить;
- **скриншоты** — обрезаны или не показывают интерфейс;
- **сбой на устройстве модератора** — поэтому шаг 5 нельзя пропускать.

**Готово, когда:** пришло письмо о публикации и приложение находится в RuStore по названию.

## Шаг 9. Версии для компьютера

Делается после шага 5, когда версия проверена. Напишите помощнику «выпусти версию 1.0.0 на GitHub» или выполните:

```bash
git tag v1.0.0
```

```bash
git push origin v1.0.0
```

Сборки запустятся снова и прикрепят файлы к странице **Releases** репозитория: установщики для Windows (`.msi`,
`.exe`), Linux (`.deb`, `.AppImage`), macOS (`.dmg`) и APK.

Установщики не имеют платной подписи разработчика:

- Windows покажет окно SmartScreen — «Подробнее» → «Выполнить в любом случае»;
- macOS не откроет приложение двойным щелчком — правый щелчок → «Открыть».

Описание выпуска с этими подсказками берётся из [release-notes.md](release-notes.md). Веб-версия по адресу `https://cacheshellpassage.github.io/kladka/` работает на любом
устройстве и ставится на главный экран телефона без магазина.

## Шаг 10. Обновления после выпуска

1. Помощник вносит изменения и поднимает версию: `pnpm set-version 1.0.1` меняет номер во всех файлах и
   увеличивает `versionCode` на единицу.
2. Код отправляется на GitHub, сборка Android даёт новый APK, подписанный **тем же ключом**. Раздел «Что нового»
   в [release-notes.md](release-notes.md) переписывается под новую версию, затем ставится метка `v1.0.1`.
3. В консоли RuStore: приложение → **Загрузить версию** → новый APK → заполнить «Что нового» конкретными
   изменениями («Добавили…», «Исправили…») → на модерацию.

RuStore не примет версию, если подпись другая или номер версии не больше предыдущего.
